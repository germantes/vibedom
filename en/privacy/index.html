Privacy

What data vibedom uses

vibedom has no accounts, no cookies and no third-party analytics. Music is synthesised in your browser. This page explains the little that does travel over the network, including an aggregate visit counter that identifies nobody.

Last updated: 26 November 2026.

The essentials

  • No sign-up, no cookies, no localStorage and no visitor identifiers.
  • No pixels and no third-party analytics.
  • The visit counter only adds up daily totals (path, channel and referring domain). No consent banner is required: it does not process personal data. If the browser sends Do Not Track or Global Privacy Control, nothing is sent.
  • We do not store the HTML, screenshots or content of analysed websites.
  • The public ranking only stores the domain and the day of each scan: never the path, the query string or your IP.
  • Music is generated in your browser; there is no pre-recorded audio or streaming.
  • Shared links carry the seed inside the URL itself, with no database behind it. If you pick the short link (the one the button copies), the seed is stored for 30 days in an external Redis so the preview card can be served; it expires on its own.

What happens when you analyse a URL

When you press “Hear my site”, your browser sends the URL you typed to our backend on Render (Frankfurt). The backend downloads the public page, extracts design signals and sends those signals to Google (Gemini or Vertex AI) to generate the Sound Seed.

  • The URL and HTML are used for that analysis. The HTML is not stored and neither is the full URL: we only add the domain (without path or query) to the public ranking, together with the day of the scan. It is not sold or used for advertising.
  • So the same visitor is not counted twice on the same day we use an in-memory hash of the IP; the IP itself is never stored. The ranking runs on Upstash (data processor), which keeps the daily counters for up to 32 days.
  • The resulting seed is kept in memory for up to 6 hours so the same URL is not analysed twice. It disappears when the process restarts.
  • The technical trace stores the host, HTTP status, size and timings for each step (for example, “css 349 KB, 200 ms”), never the full path or the content.
  • Render and Google may retain technical request logs under their own policies. We do not control those logs.

If you do not want to send a URL, you can listen to the demo presets or generate a local seed without going through the AI.

What happens with the widget

The embeddable widget does not call the vibedom API or the AI. The seed travels inside the snippet's own data-seed, so every visitor hears the variation without sending the host page's URL anywhere.

  • It uses no cookies or localStorage.
  • It does not take part in the visit counter: the embedded script does not call the backend.
  • The first click downloads Tone.js from jsDelivr, which sees the visitor's IP like any CDN.
  • Audio is synthesised in the browser; no music is downloaded and nothing is uploaded.

Visit counter

When you open a page on vibedom.dev, the browser may tell the backend with a single request. It exists so we can see which channel people arrive from (?ref=hn, ?ref=reddit and the like, or utm_source when there is no ref).

  • The page path, without the query string or the fragment.
  • The language of that page (es or en).
  • The channel, if the URL has ref or, failing that, utm_source.
  • The domain of the site that linked to you: the host only, never the full URL.

Nothing is sent if the browser signals Do Not Track or Global Privacy Control.

The counter does not store:

  • the IP address, or a hash of the IP;
  • cookies, localStorage or any identifier;
  • the query string, the referrer path or a browser fingerprint.

The IP is looked at only in memory, and only for a minute, to limit bursts. It is not written into the counter. What is kept is a total per day, path, channel and referring domain. Those totals expire after 40 days. They live in the same Upstash Redis as the ranking, not on Render's disk: on the free plan that disk is lost when the service sleeps or restarts. Without Upstash credentials, the totals stay in the process memory and disappear with it.

No consent banner is required. The counter does not identify a person: the figures are aggregates, with no cookies and no identifiers, and it stays silent under Do Not Track or Global Privacy Control. It is therefore not a processing of personal data that requires consent under the GDPR.

Render may keep technical logs of the request under its own policy. We do not control that, and it is not part of the counter.

External services

  • Render: hosts the backend that analyses URLs and serves shared-link previews.
  • GitHub Pages: serves the static site at vibedom.dev.
  • Google: Gemini or Vertex AI generate the seed; Google Cloud bills the project's usage.
  • Upstash: stores the aggregated ranking counters (domain and day) and the daily visit totals (path, channel and referring domain) in Redis.
  • jsDelivr: delivers Tone.js when you press play in the demo or the widget.

We do not use advertising networks, Google Analytics or marketing cookies. The only count is the first-party counter described above. We do not build visitor profiles.

Your rights and contact

Since there are no accounts or profiles, there is no profile to delete. The ranking and the visit counter only contain aggregated totals, with no IPs or personal data. If you have questions about this processing or want to exercise your access, rectification or erasure rights, email gtorrestendero@gmail.com.

If what vibedom does changes, we will update this page and the date above. The project is open source and you can review the processing on GitHub.
